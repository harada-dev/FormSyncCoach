# デモデータ(出所と注意)

**作成:** 2026-08-18 / 生成環境: Windows, Python 3.14, mediapipe 1.0.1, opencv-python 5.0.0

## ⚠️ これは実際のキック動作のデータではない

`test.mp4` は **MediaPipe公式のサンプル人物画像を平行移動させて作った合成動画**であり、キック動作ではない。
パイプラインが端から端まで通ることを確認するためのスモークテスト用フィクスチャ。
**この動画はリポジトリに含めていない**(`make_testvideo.py` でいつでも再生成できるため。下記「再現手順」の1行目)。

したがって:

- `metrics.csv` に入っている角度・角速度の**値そのものに生体力学的な意味はない**。
- 特に角速度のピーク(膝伸展 約180 deg/s、下腿 約195 deg/s)は合成動画のパン運動由来のアーティファクト。
- `docs/reference-values.md` の文献値と比較してはならない。

実データでの妥当性検証は未実施。

## 再現手順

`docs/analysis-toolkit/` のスクリプトを使う。依存は `mediapipe opencv-python numpy scipy` の4つ。
1行目の `make_testvideo.py .` がこのディレクトリに `test.mp4` を生成する(未収録のため必須)。以降の2行はそれを入力にして、収録済みの `landmarks.csv` / `metrics.csv` を再生成する。

```
python make_testvideo.py .
python pose_to_csv.py test.mp4 -o landmarks.csv --model heavy
python kick_metrics.py landmarks.csv --leg right --m-per-px 0.0025 -o metrics.csv
```

`--m-per-px 0.0025` は合成動画に対する便宜的な値で、実測校正ではない。実データではボール直径(5号球 0.22 m)の画素径から算出すること。

## 検証済みの範囲

- **線形代数部分:** `kick_metrics.py --selftest` が既知形状(膝屈曲90°→30°の直線変化)で通る。角度の最大誤差 1.4e-14 deg、角速度 3.0e-12 deg/s、骨盤ローカル系の回転不変性 3.8e-17 m。
- **パイプライン疎通:** 動画 → CSV → 指標算出まで完走。96/96フレーム検出。
- **未検証:** 実際のキック動作での妥当性、マーカー式との比較、試技間再現性(PRD G6 の ±5° 要件)。

## 既知の制約(iOS実装への申し送り)

- MediaPipe 1.0 で旧 `mp.solutions.pose` API は削除済み。Tasks API のみ。
- `pose_world_landmarks` は原点が左右股関節の中点。**並進が消えるため絶対速度が出ない。** 絶対速度が要る指標は画像座標+スケール校正、または接地足を基準にした並進成分の復元が必要(`reference-values.md` §7 を参照。同節は解決済みで、アプリ側の「9.67」が m/s ではなく正規化画像座標/秒だったことが結論)。
- 足部ランドマークは踵とつま先のみ。足関節角は「下腿−足部長軸」の近似であり距腿関節角ではない。
- セグメント角速度は ω = u × u̇ で算出しており、**セグメント軸まわりの自転(下腿の内外旋)は原理的に観測できない**。
- 接触フレーム検出は「足部速度ピーク直後の最大減速点」というヒューリスティック。240 fps でも ±1フレーム(±4 ms)の曖昧さが残る。
